# AGENTS.md

이 문서는 이 저장소에서 작업하는 AI 코딩 에이전트를 위한 지침입니다.
작업을 시작하기 전에 끝까지 읽고, 규칙과 충돌하는 요청이 있으면 임의로 진행하지 말고 먼저 확인하세요.

## 1. 프로젝트 개요
- **핵심 기능**
  1. 우측 상단 헤더에 현재 날씨 표시 (Open-Meteo API 연동)
  2. 더미 데이터 기반의 다양한 차트로 구성된 대시보드 페이지
- "가장 짧은 코드"보다 **"읽고 이해하기 쉬운 코드"**를 우선합니다.

## 2. 기술 스택

| 영역 | 선택 | 비고 |
| --- | --- | --- |
| 빌드 도구 | Vite | `npm create vite@latest` (react 템플릿, JavaScript) |
| 언어 | JavaScript (ES2022+, .jsx) | `any` 금지, TypeScript 사용 안 함 |
| UI | React 18+ (함수형 컴포넌트, Hooks) | 클래스 컴포넌트 금지 |
| 차트 | Recharts | 다른 차트 라이브러리 추가 금지 |
| 스타일 | CSS Modules (`*.module.css`) + `src/styles/tokens.css` | Tailwind, CSS-in-JS 사용 안 함 |
| 카드 배치/크기 조절 | react-grid-layout | 드래그 이동 + 리사이즈 전용. 이 용도 외 사용 금지 |
| 데이터 요청 | 브라우저 내장 `fetch` + 커스텀 훅 | axios, React Query 도입 금지 (학습 범위 밖) |
| 린트/포맷 | ESLint + Prettier | 기본 설정 유지 |

새 의존성이 필요하다고 판단되면 **설치하지 말고** 이유와 함께 먼저 제안하세요.

## 3. 명령어

```bash
npm install        # 의존성 설치
npm run dev        # 개발 서버 (http://localhost:5173)
npm run build      # 타입 체크 + 프로덕션 빌드
npm run lint       # ESLint
npm run preview    # 빌드 결과 미리보기
```

작업을 마치기 전에 `npm run lint`와 `npm run build`가 모두 통과해야 합니다.

## 4. 디렉터리 구조

```
src/
├─ main.jsx
├─ App.jsx
├─ components/
│  ├─ layout/        # Header, DashboardLayout, DashboardGrid (리사이즈/이동 로직)
│  ├─ weather/       # WeatherWidget 및 하위 UI
│  ├─ charts/        # 차트 컴포넌트 (차트 1종 = 파일 1개)
│  └─ common/        # Card, KpiCard, Skeleton, ErrorMessage 등 재사용 UI
├─ hooks/
│  ├─ useWeather.js        # 날씨 데이터 로딩 로직
│  └─ useLayoutStorage.js  # 카드 레이아웃 저장/복원/초기화
├─ api/
│  └─ weather.js      # Open-Meteo 호출 함수 (fetch 로직은 여기에만)
├─ data/             # 더미 데이터 (차트별 파일 분리), defaultLayouts.js
├─ constants/        # 공용 상수 (API 주소, 저장 키, 색상 팔레트 등)
├─ utils/            # 순수 함수 (포맷터, 날씨 코드 매핑 등)
└─ styles/
   └─ tokens.css     # 색상, 간격, 폰트 등 CSS 변수
```

- 컴포넌트 파일명은 PascalCase, 훅은 `useXxx`, 그 외는 camelCase.
- 컴포넌트와 스타일은 같은 폴더에 둡니다. (`WeatherWidget.tsx` + `WeatherWidget.module.css`)

## 5. 날씨 위젯 사양 (Open-Meteo)

### API
- 엔드포인트: `https://api.open-meteo.com/v1/forecast`
- **API 키 불필요.** 키나 시크릿을 코드/환경변수에 만들지 마세요.
- 기본 위치: 서울 (위도 `37.5665`, 경도 `126.9780`), `timezone=Asia/Seoul`
- 요청 파라미터 예시:
  ```
  ?latitude=37.5665&longitude=126.978
  &current=temperature_2m,relative_humidity_2m,apparent_temperature,weather_code,wind_speed_10m
  &timezone=Asia%2FSeoul
  ```
- 위도/경도/도시명은 `src/api/weather.ts` 상단 상수로 분리해 수강생이 쉽게 바꿔볼 수 있게 합니다.

### 표시 위치와 내용
- 헤더의 **우측 상단**에 고정 배치합니다.
- 표시 항목: 도시명, 현재 기온(°C), 날씨 상태 아이콘(이모지 가능) + 한글 설명, 체감 온도, 습도, 풍속
- 날씨 코드(WMO) → 한글 설명/아이콘 변환은 `src/utils/weatherCode.ts`에 매핑 객체로 작성합니다.

### 상태 처리 (필수)
세 가지 상태를 모두 구현합니다. "비동기 UI의 기본 3상태"를 보여주는 것이 목적입니다.
1. **로딩**: 스켈레톤 UI
2. **에러**: 짧은 에러 메시지 + "다시 시도" 버튼
3. **성공**: 날씨 정보 표시

### 구현 규칙
- 데이터 로딩은 `useWeather` 훅으로 캡슐화하고 `{ data, isLoading, error, refetch }`를 반환합니다.
- `useEffect` 안에서 요청 시 **`AbortController`로 언마운트 시 요청을 취소**하고, 주석으로 이유를 설명합니다.
- 응답은 `src/types`에 정의한 타입으로 변환해 컴포넌트에 전달합니다. (컴포넌트가 API 응답 구조를 직접 알지 않도록)
- 새로고침 주기는 10분(선택). 구현한다면 `setInterval` 정리(cleanup)를 반드시 포함합니다.

## 6. 대시보드 사양 (더미 데이터)

모든 데이터는 `src/data/`의 **정적 더미 데이터**입니다. 차트용 데이터를 위해 외부 API를 호출하지 마세요.
`Math.random()`으로 렌더링마다 값이 바뀌지 않게, 고정된 값이나 시드 기반 생성을 사용합니다.

### 구성 요소

| 영역 | 내용 |
| --- | --- |
| KPI 카드 4개 | 매출, 방문자, 전환율, 주문 수 (증감률 ▲▼ 표시) |
| 라인 차트 | 최근 12개월 매출 추이 (2개 시리즈 비교) |
| 영역 차트 | 일별 방문자 수 (30일) |
| 막대 차트 | 카테고리별 판매량 (세로 막대) |
| 누적 막대 차트 | 분기별 채널(온라인/오프라인/모바일) 매출 |
| 도넛 차트 | 유입 경로 비율 |
| 레이더 차트 | 제품별 만족도 항목 비교 |
| 산점도 | 광고비 대비 매출 |
| 복합 차트 | 막대 + 라인 (매출 + 전환율, Y축 2개) |
| 테이블 | 최근 주문 목록 5~10건 |

- 차트는 최소 6종 이상, 위 목록 전부를 목표로 합니다.
- 각 차트는 `Card` 컴포넌트로 감싸고 제목과 한 줄 설명을 표시합니다.
- 차트 컴포넌트는 **데이터를 props로 받습니다.** 더미 데이터 import는 페이지(`App` 또는 `DashboardPage`)에서만 합니다. (props 흐름 학습 목적)
- `ResponsiveContainer`를 사용해 반응형으로 만들고, 툴팁과 범례를 포함합니다.

### 레이아웃
- `react-grid-layout`의 `Responsive` + `WidthProvider` 기반. 브레이크포인트별 컬럼 수: lg(≥1200) 12, md(≥768) 6, sm(<768) 2 또는 1.
- 카드 크기 조절과 이동은 7번 섹션을 따릅니다.
- 색상은 `tokens.css`의 CSS 변수만 사용하고, 차트 색상 팔레트도 한 곳에서 관리합니다.
- 다크 모드는 범위 밖입니다. 요청받기 전에 추가하지 마세요.

## 7. 카드 크기 조절 / 이동 사양

모든 대시보드 카드(KPI 카드, 차트 카드, 테이블 카드)는 사용자가 **크기를 조절**할 수 있어야 합니다.

### 동작
- 카드 **우하단 모서리 핸들을 드래그**해 너비(컬럼 수)와 높이(행 수)를 조절합니다.
- 카드 **헤더(제목 영역)를 드래그**해 위치를 옮길 수 있습니다. 핸들 클래스는 `draggableHandle=".card-drag-handle"`로 지정해, 차트 안의 툴팁/클릭과 드래그가 충돌하지 않게 합니다.
- 크기 조절 중에도 차트가 컨테이너에 맞춰 다시 그려져야 합니다. (`ResponsiveContainer`는 부모의 `width/height: 100%`를 따르므로, 카드 본문이 남은 높이를 채우도록 flex로 구성)
- 각 카드에 **최소/최대 크기**를 지정합니다. (`minW`, `minH`, `maxW`, `maxH`) 차트가 찌그러지거나 텍스트가 잘리지 않는 값으로 정합니다.
- 헤더 영역에 **"레이아웃 초기화"** 버튼을 둡니다. (기본 배치로 복원)
- 편집 모드 토글(선택): "레이아웃 편집" 버튼을 켰을 때만 드래그/리사이즈 핸들이 활성화되게 하면 평소 사용 중 오조작을 줄일 수 있습니다. 구현은 `isDraggable` / `isResizable`에 상태를 연결하는 것으로 충분합니다.

### 구조
- 기본 레이아웃은 `src/data/defaultLayouts.js`에 브레이크포인트별(`lg`, `md`, `sm`)로 정의합니다. 카드 `id`는 레이아웃 항목의 `i`와 동일하게 사용합니다.
- 사용자가 바꾼 레이아웃은 `localStorage`에 저장하고 새로고침 후에도 복원합니다. 저장/복원은 `src/hooks/useLayoutStorage.js` 훅으로 분리하고, 다음을 지킵니다.
  - 저장 키는 상수로 분리하고 버전을 포함합니다. (예: `dashboard-layout-v1`)
  - `JSON.parse`는 `try/catch`로 감싸고, 실패하거나 형식이 맞지 않으면 기본 레이아웃으로 되돌립니다.
  - 카드가 추가/삭제되어 저장된 레이아웃과 `id`가 어긋나면 기본 레이아웃을 사용합니다.
- `Card` 컴포넌트는 크기 조절을 직접 알지 못합니다. 레이아웃 로직은 `DashboardGrid` 컴포넌트에 모읍니다. (관심사 분리 학습 포인트)
- 카드 컴포넌트에 붙는 `style`, `className`, `ref` 등을 react-grid-layout이 주입하므로, 카드 래퍼는 `forwardRef` 또는 단순 `<div>`로 감싸 사용합니다.

### 주의
- `react-grid-layout/css/styles.css`와 `react-resizable/css/styles.css`를 import 해야 핸들이 정상 표시됩니다. 리사이즈 핸들 모양은 `tokens.css` 변수를 사용해 커스터마이즈합니다.
- 모바일(sm)에서는 리사이즈를 비활성화하고 한 열로 쌓이게 합니다. 터치 환경에서의 오조작을 막기 위함입니다.
- 키보드 사용자를 위해, 편집 모드가 켜진 카드에는 "크기 조절은 마우스/터치 드래그로 지원됩니다"라는 안내 문구를 화면에 둡니다. 완전한 키보드 리사이즈는 범위 밖입니다.

## 8. 코드 스타일 규칙

- 함수형 컴포넌트와 `const`/화살표 함수를 사용하고, `var`는 금지합니다. 비교는 `===`를 사용합니다.
- 컴포넌트 props는 매개변수에서 구조 분해하고, 필수/선택 구분이 필요하면 JSDoc 또는 `PropTypes`로 명시합니다. (PropTypes를 쓸 경우 `prop-types` 설치를 먼저 제안)
- 컴포넌트 하나는 약 100줄 이내를 지향합니다. 넘으면 분리합니다.
- 매직 넘버/문자열은 상수로 분리합니다.
- 인라인 스타일 지양 (동적 값이 꼭 필요한 경우만).
- 접근성: 의미 있는 HTML 태그(`header`, `main`, `section`, `table`), 아이콘에는 `aria-label` 또는 대체 텍스트, 버튼은 `<button>` 사용.
- 상태는 가능한 한 가장 가까운 컴포넌트에 둡니다. 전역 상태 라이브러리는 사용하지 않습니다.

## 9. 교육용 코드 원칙 (중요)

1. **주석은 "무엇"이 아닌 "왜"**를 설명합니다. 한국어로 작성합니다.
   - 좋은 예: `// 컴포넌트가 사라진 뒤 setState가 호출되지 않도록 요청을 취소합니다.`
   - 나쁜 예: `// 상태를 설정합니다`
2. 핵심 개념이 처음 등장하는 곳에 짧은 학습 포인트 주석을 둡니다. (`// * 학습 포인트: ...`)
   - 대상 개념: props 전달, `useState`, `useEffect`와 cleanup, 커스텀 훅, 조건부 렌더링, 리스트 렌더링과 `key`, 로딩/에러/성공 상태 분리, 레이아웃 상태 관리와 `localStorage` 연동
3. 영리하지만 난해한 패턴(과도한 제네릭, 중첩 삼항, reduce 체이닝 등)은 피합니다.
4. 추상화는 필요할 때만 합니다. 파일을 과하게 쪼개 흐름을 따라가기 어렵게 만들지 마세요.
5. 학습 포인트 주석은 파일당 많아야 2~3개로, 코드를 덮을 만큼 많지 않게 합니다.

## 10. 하지 말아야 할 것

- 지침에 없는 라이브러리 설치 (상태 관리, UI 키트, 라우터 포함). 카드 배치/리사이즈용 `react-grid-layout`(과 그 의존성 `react-resizable`)만 예외입니다.
- 카드 리사이즈를 직접 구현하겠다고 `mousemove` 이벤트를 수동 처리하는 코드 작성 (라이브러리 사용)
- API 키가 필요한 서비스 연동, `.env`에 비밀 값 추가
- 테스트 통과나 빌드 성공을 위해 린트 규칙을 `eslint-disable`로 끄고 넘어가기
- 요청 범위를 벗어난 대규모 리팩터링, 폴더 구조 변경
- 수강생 데이터나 실제 개인정보로 보이는 더미 데이터 사용 (이름은 명백한 가상 이름 사용)

## 12. 작업 방식

- 한 번에 모두 만들지 말고 다음 순서로 진행하며, 단계마다 동작을 확인합니다.
  1. 프로젝트 생성과 폴더 구조, 디자인 토큰
  2. 레이아웃(Header + 그리드)과 공용 `Card`
  3. 날씨 API 함수, 훅, 위젯 (로딩/에러/성공)
  4. 더미 데이터와 차트 컴포넌트 (이 단계에서는 고정 그리드로 먼저 배치해 확인)
  5. `DashboardGrid` 도입: 고정 그리드를 react-grid-layout으로 교체해 리사이즈/이동, 기본 레이아웃, 저장/초기화 구현
  6. 대시보드 조립, 반응형 점검
  7. README 작성, 린트/빌드 최종 확인
- 요구사항이 모호하면 가정을 README 하단 "가정 사항"에 기록하고 진행합니다.
- 작업이 끝나면 변경한 파일 목록, 실행 방법, 남은 이슈를 짧게 요약합니다.
